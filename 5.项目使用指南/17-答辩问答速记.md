## 一、数据与划分

### Q1. 训练集、验证集、测试集各多少？猫狗各多少？

**一句话答案：** 原始标注池 **22500** 张（猫 **11250**、狗 **11250**），按 **9:1** 切成训练 **20250** 张、验证 **2250** 张；另有独立测试集 **2500** 张（猫 **1250**、狗 **1250**）。所以最终三者是 **20250 : 2250 : 2500 = 81% : 9% : 10%**。

**为什么：** 先把 **2500** 张锁成测试集、全程不参与调参；剩下的 **22500** 张再切 **10%** 做验证，用来选最优权重和早停。

| 集合 | 总数 | 猫 | 狗 | 比例（占全部 25000） |
|---|---|---|---|---|
| 原始标注池（train 目录） | **22500** | **11250** | **11250** | 90% |
| 最终训练集 | **20250** | **10126** | **10124** | **81%** |
| 验证集 | **2250** | **1124** | **1126** | **9%** |
| 测试集 | **2500** | **1250** | **1250** | **10%** |

- 训练/验证的猫狗数是按 `split_seed=42` 实际切出来的（`cache/train_labels.npy` + `src/data.py:101-105` 复算），因为切分只随机打乱、不强制分层，所以是 **10126/10124** 而不是严格的 10125/10125。
- 训练:测试 = **20250 : 2500 ≈ 89 : 11**；如果只问「标注池:测试」则是 **22500 : 2500 = 90 : 10**。

### Q2. 数据集来源是什么？

**一句话答案：** 老师提供的 `Cat_Dog_data`，即 **Kaggle Dogs vs. Cats（猫狗大战）** 的 **25000** 张标注图，猫狗各 **12500** 张；目录为 `d:\DeepStudy\Project1\Cat_Dog_data`，下设 `train/{cat,dog}` 与 `test/{cat,dog}`。

**为什么：** 目录结构与数量完全对应 Kaggle 版本（猫狗各半、共 **25000** 张）；项目里的 `test` 是老师从标注池中划出的 **2500** 张带标签图片，不是 Kaggle 原始的无标注 test。

- 数量核对：`check_data.py:11-12` 的期望值就是 train 每类 **11250**、test 每类 **1250**；实际文件计数一致。
- 目录里没有原始下载链接的说明文件，答辩时按「课程提供 / Kaggle Dogs vs. Cats」表述即可。

## 二、训练配置

### Q3. 每个实验的 batch size 是多少？

**一句话答案：** 迁移学习（E6 的 A/B 两阶段）用 **32**；自搭 CNN 的 E1（6 个 run）和 E7（3 个 run）都用 **48**。

**为什么：** ResNet18 参数多、显存占用大，用 **32** 更稳；自搭 CNN 小，用 **48** 提高吞吐。两组是分两条命令跑的，所以 batch 不同。

| 实验 | run | batch size | 出处 |
|---|---|---|---|
| E6 阶段 A（冻结） | `resnet_stageA_s42/43/44` | **32** | `config.json`；README 命令 |
| E6 阶段 B（微调） | `resnet_stageB_s42/43/44` | **32** | 同上 |
| E1 无增强 | `cnn_gap_aug_off_s42/43/44` | **48** | `config.json`；命令 `--batch-size 48` |
| E1 有增强 / E2 自搭 CNN / E7 GAP | `cnn_gap_aug_on_s42/43/44` | **48** | 同上 |
| E7 大 FC | `cnn_heavy_aug_on_s42/43/44` | **48** | 同上 |

> 注意：`batch_size` 是全局参数（`run_experiments.py:36,40,80`），一条命令里所有组共用。**E2 的「自搭 48 vs 迁移 32」是一个混杂因素**，已在报告局限里写明。

### Q4. 每个实验的 epoch 上限和实际跑完轮数？

**一句话答案：** 上限是阶段 A **6**、阶段 B **8**、自搭 CNN **12**；实际因早停，阶段 A 跑了 **6/5/6**，阶段 B **5/7/8**，E1 无增强 **12/6/12**、有增强 **12/12/12**，E7 大 FC **12/7/12**。

**为什么：** 上限是硬上限（`engine.py:120` 的 `range(1, epochs+1)`），验证 loss 连续 `patience` 轮不降就提前停（`engine.py:150-163`）。

| 实验 | run | 上限 | 实际（s42 / s43 / s44） | 平均 |
|---|---|---|---|---|
| E6 阶段 A | `resnet_stageA_s*` | **6** | **6 / 5 / 6** | **5.7** |
| E6 阶段 B | `resnet_stageB_s*` | **8** | **5 / 7 / 8** | **6.7** |
| E1 无增强 | `cnn_gap_aug_off_s*` | **12** | **12 / 6 / 12** | **10.0** |
| E1 有增强 / E2 / E7 GAP | `cnn_gap_aug_on_s*` | **12** | **12 / 12 / 12** | **12.0** |
| E7 大 FC | `cnn_heavy_aug_on_s*` | **12** | **12 / 7 / 12** | **10.3** |

- 上限来源：`run_experiments.py:76-79` 的默认值（CNN 默认 **20**，报告用的是命令显式传的 **12**）。
- 实际上限写在每个 spec 的 `epochs` 字段（`run_experiments.py:46-67`），实际轮数 = `history.json` 的长度。
- patience：迁移 **2**（`run_experiments.py:48,51`），自搭 CNN **3**（`:59,62,67`）。

### Q5. 一共跑了几次训练？怎么构成？

**一句话答案：** 正式结果 **15 个 run = 6 个迁移 + 6 个 E1 + 3 个 E7**；每个 run 训练 **1** 次，训练结束后再做 **1** 次最终测试评估，共 **15 次训练 + 15 次测试**。

**为什么：** 每个实验 **3 个种子**（42/43/44），迁移每个种子要 A/B 两阶段，所以 **3×2=6**；E1 是「增强开/关」两组，**3×2=6**；E7 只跑 GAP 的对照大 FC 头，**3×1=3**。

- 构成明细：`resnet_stageA/B_s42/43/44`（6）、`cnn_gap_aug_on/off_s42/43/44`（6）、`cnn_heavy_aug_on_s42/43/44`（3）。
- 另有 1 次 **5 个 run 的冒烟测试**（1 epoch、每轮 3 个 batch），只验证链路，不计入正式结果，且 s42 的目录已被正式结果覆盖。

### Q6. 学习率是多少？优化器是什么？迁移学习分层了吗？

**一句话答案：** 所有实验基础学习率都是 **1e-3**，优化器都是 **Adam**；迁移阶段 B **分层**：layer4 用 **1e-4**（基础值的 0.1 倍），新分类头用 **1e-3**。

**为什么：** 预训练卷积层只需要轻轻调，学习率大了会把 ImageNet 特征「洗掉」；新分类头是随机初始化，需要正常学习率。

| 阶段 | 可训练部分 | 优化器 | 学习率 |
|---|---|---|---|
| 迁移阶段 A | 只有新 `fc`（**1026** 个参数） | Adam | **1e-3** |
| 迁移阶段 B | **优化器只更新** layer4 + `fc`（**8,394,754**） | Adam | layer4 **1e-4**，fc **1e-3** |
| 自搭 CNN（E1/E7） | 全部参数 | Adam | **1e-3** |

- 出处：`run_experiments.py:47,50,58,61,66`（`lr=1e-3`）；`src/runner.py:86-95`（阶段 B 分层，`lr*0.1`）。
- 实测参数：阶段 A `metrics.json` 的 `params_trainable=1026`；阶段 B 记录的是 **11,177,538**，因为 `build_model` 对阶段 B 没有冻结 backbone（`runner.py:76` 只在 A 阶段冻结），全模型 `requires_grad=True`。但阶段 B 的优化器只收了 layer4 和 fc（`runner.py:89-92`），实际更新 **8,394,754** 个参数，conv1–layer3 保持预训练值不动。

### Q7. 学习率调度用的是什么？

**一句话答案：** **CosineAnnealingLR**（余弦退火），`T_max = 该 run 的 epoch 上限`，`eta_min = 基础学习率 × 0.01 = 1e-5`，每个 epoch 走一步。

**为什么：** 前期学习率大、后期平滑降到很小，不用手工设「第几轮降多少」，也比阶梯式更稳。

- 出处：`src/runner.py:97`；`engine.py:128-129` 在每个 epoch 末尾 `scheduler.step()`。
- 阶段 B 两组都退到 **1e-5**：layer4 从 **1e-4 → 1e-5**，fc 从 **1e-3 → 1e-5**（`eta_min` 是绝对值，没有按组缩放）。

### Q8. Dropout 在哪、p 是多少？

**一句话答案：** 自搭 CNN 有 **3** 处：`fc1` 前 p=**0.5**、`fc2` 前 p=**0.5**、`fc3` 前 p=**0.3**；ResNet18 新分类头在最终 `Linear` 前有 **1** 处 p=**0.3**。

**为什么：** 全连接层参数最多、最容易过拟合，所以在每个 FC 前丢一部分神经元；最后一层前降到 **0.3**，避免把有效特征丢太多。

- 出处：`src/models.py:62,65,68`（定义）、`:81-85`（调用）；ResNet 在 `:109,123-125`。
- Dropout 只在 `model.train()` 生效，评估时自动关闭（`engine.py` 的 `evaluate` 会 `model.eval()`）。

### Q9. 自搭 CNN 的卷积、池化、全连接各几个？卷积核和通道数？

**一句话答案：** **7 个卷积、4 个池化、3 个全连接**；卷积核全是 **3×3、padding=1**，通道数 **32→64→128→256**；池化都是 **2×2、步长 2**。

**为什么：** 每个卷积块「卷积提特征 + 池化降尺寸」，通道翻倍、分辨率减半，最后 **14×14×256** 送进分类头。

| 阶段 | 组成 | 输出形状（batch 省略） |
|---|---|---|
| 输入 | — | **3×224×224** |
| b1 | **2** 个 Conv3×3+BN+ReLU，1 个 MaxPool2×2 | **32×112×112** |
| b2 | **2** 个 Conv3×3+BN+ReLU，1 个 MaxPool2×2 | **64×56×56** |
| b3 | **2** 个 Conv3×3+BN+ReLU，1 个 MaxPool2×2 | **128×28×28** |
| b4 | **1** 个 Conv3×3+BN+ReLU，1 个 MaxPool2×2 | **256×14×14** |
| GAP 头 | 全局平均池化 + 3 层 FC | **256 → 512 → 256 → 2** |
| 大 FC 头（E7 对照） | 展平 + 3 层 FC | **50176 → 512 → 256 → 2** |

- 出处：`src/models.py:55-69`（结构）、`:24`（Conv 参数）、`:29`（MaxPool）。
- 参数量：GAP 版 **0.848M**，大 FC 版 **26.407M**，ResNet18 **11.178M**（`metrics.json` / 汇总表）。

### Q10. 归一化怎么做？BN 放在哪？

**一句话答案：** 输入先除以 **255**，再按 ImageNet 均值 **(0.485,0.456,0.406)**、标准差 **(0.229,0.224,0.225)** 标准化；BN 在自搭 CNN 的**每个卷积后**和 **fc1、fc2 后**，ResNet18 用自带的 BN，新分类头不再加 BN。

**为什么：** 和 ImageNet 预训练权重的输入分布对齐；BN 让每层输入稳定，收敛更快、能用 **1e-3** 这种较大学习率。

- 出处：`src/data.py:22-23,47-52`；BN 在 `src/models.py:25-26`（Conv 后）、`:64,67`（FC 后）；有 BN 时卷积 `bias=False`（`:24`）。

### Q11. 输入尺寸、预处理和数据增强具体是什么？

**一句话答案：** 缓存统一 **256×256**；训练时随机裁到 **224×224**，并做水平翻转（p=**0.5**）、±**12°** 旋转、颜色抖动（亮度/对比度/饱和度 **0.2**、色调 **0.02**）；验证/测试只做 **224** 中心裁剪，不加任何随机。

**为什么：** 训练增强让模型见过更多视角和光照，减少过拟合；验证/测试必须确定性，否则同一模型两次评估结果都不一样。

- 出处：`prepare_cache.py:28`（**SIZE=256**）；`src/data.py:29-44`；`src/runner.py:67-68`（统一裁 **224**）。
- 增强是在 **GPU** 上用 `torchvision.transforms.v2` 做的，输入是 uint8 张量，省掉 CPU 解码和数据搬运。

### Q12. 损失函数和评价指标是什么？

**一句话答案：** 损失是 **CrossEntropyLoss**（多分类交叉熵，二分类同样适用）；主指标是**测试准确率**，训练过程中用**验证 loss** 早停、用**验证准确率**选最优权重，另外用混淆矩阵和错误样本做定性分析。

**为什么：** 类别平衡（猫狗各半），不需要加权损失；准确率直观、和评分标准一致，混淆矩阵能补充「错在哪一类」。

- 出处：`src/runner.py:84`（criterion）、`src/engine.py` 的 `evaluate()`（返回 loss、acc、y_true、y_pred、y_prob）。
- 没有额外计算 F1/AUC，答辩时不要说「我们算了 F1」。

## 三、结果

### Q13. 主结果和四组实验的关键数字？

**一句话答案：** 主结果是 **ResNet18 阶段 B：98.72% ± 0.18%**；四组结论：增强**主要买到稳定性**（最差种子 **78.88%→91.08%**，std **8.04→0.53**、方差约 **230 倍**，均值 **+3.51** 主要由 s43 一次崩盘贡献），迁移比自搭 CNN **+7.05**，微调比只训头 **+0.91**，GAP 与大 FC **准确率不可区分**，赢在参数少 **31 倍**、方差小约 **78 倍**。

**为什么：** 预训练特征 + 微调最适合这个小数据集；增强主要买「稳定」；大 FC 在 2 万张图上参数冗余、反而更抖。

## 四、老师可能追问（口语化）

### 1. 为什么选 ResNet18？

我们数据只有 **2 万多张**，ResNet18 只有 **11.18M** 参数，8GB 显存跑得动，ImageNet 预训练特征也够用；阶段 B 三个种子平均 **98.72%**，单个 run 只要 **2.8 分钟**。再大的模型在这个数据量上收益不一定抵得过过拟合和训练成本，所以先用 ResNet18 把基线做扎实。

### 2. 为什么先冻结再微调？

因为新换的分类头是随机初始化的，一上来就全网络训练，大梯度会把预训练特征冲掉。阶段 A 只训头（**1026** 个参数）拿到 **97.81%**，阶段 B 再解冻 layer4 用小学习率微调，升到 **98.72%**，多 **0.91** 个点，说明「先稳后调」是有效的。

### 3. 为什么用 GAP，不用大 FC？

GAP 版 **0.848M** 参数，大 FC 版 **26.407M**，差 **31 倍**。准确率其实**分不出来**：均值 91.67% vs 90.76% 只差 0.91 个点，小于大 FC 自己 4.68% 的波动；中位数还是大 FC 更高（**93.28 vs 91.80**），三个种子里**两个是大 FC 赢**。所以准确的说法是「**同等精度下参数少 31 倍、方差小约 78 倍**」，选 GAP 是为了参数效率和稳定，不是因为它更准。

### 4. 为什么必须做数据增强？

E1 里无增强 **88.16% ± 8.04%**、有增强 **91.67% ± 0.53%**，但均值 +3.51 主要是 **s43 一次崩盘**贡献的（逐种子 +0.44 / +12.92 / +1.96），无增强**中位数 92.56%** 其实比有增强的 91.80% 还高。真正拉开差距的是方差：**8.04 对 0.53，约 230 倍**，最差种子从 **78.88%** 被抬到 **91.08%**。s43 那次是早停切在了验证准确率仍在上涨的第 6 轮（验证 loss 在 ep3 触底 0.424、ep5 尖峰 0.904，连续 3 轮没改善就停），所以增强买的是「不崩」，不是「每次多 3 个点」。

### 5. 为什么是 90:10，不是 8:2？

验证集 **2250** 张时，准确率的标准误在 **0.3~0.6** 个百分点（准确率 98% 时约 **0.3**，90% 时约 **0.6**），已经够判断模型好坏；如果改成 8:2，验证虽然变多，但训练会从 **20250** 掉到 **18000**，少 **11%** 的数据，对小数据集不划算。测试集 **2500** 张是完全独立的，不参与这个划分。

### 6. 单卡怎么在有限时间内跑完？

先把 25000 张图预解码成 **256** 的缓存（约 **5.5 分钟**），训练时不再解 JPEG；增强放在 GPU 上做；用 AMP 混合精度；迁移学习先冻结、只训头；自搭 CNN 只跑 **12** 轮并加早停。15 个 run 纯训练约 **82 分钟**，加缓存和最终评估约 **1.5 小时**。

### 7. 怎么判断过拟合、怎么处理？

主要看训练 loss 和验证 loss 的曲线：训练一路降、验证开始回升或准确率停滞，就是过拟合信号；无增强那组 seed43 验证 loss 很快不再改善，早停在 **6** 轮、测试只有 **78.88%**。处理上是数据增强、Dropout（**0.5/0.5/0.3**）、按验证 loss 早停、按验证准确率保存最优权重，而不是拿最后一轮去测试。

### 8. 这套代码和 Part 7 / Part 8 notebook 什么关系？

Part 7 解决「图怎么读进来」：`ImageFolder`、`transforms`、`DataLoader`，对应项目里的 `src/data.py`；Part 8 讲迁移学习的「冻结 → 换头 → 解冻微调」，对应 `src/models.py` 和 `src/runner.py` 的阶段 A/B。项目是把 notebook 里的单次实验拆成模块，再加上缓存、AMP、多种子、实验编排和自动出图。

### 9. 你这套代码里最容易出错的地方是哪？

第一是冻结顺序：必须先冻结 backbone 再换头，反了新分类头也会被冻住，训练时 loss 不动（`models.py:113` 的注释就是踩过这个坑）。第二是 Windows 上 `num_workers` 开太大，每个子进程重新 import torch，GPU 一直 0%。第三是改了输入尺寸却忘了改 `models.py` 里写死的 `14*14`，全连接层会形状不匹配。

### 10. 这套工作有哪些局限？

一是 E2 里自搭 CNN 用 **48**、迁移用 **32**，batch 不同，严格说不是单变量对比；二是每格只有 **3 个种子**，成绩最好的组均值 95% 置信区间约 **±0.46** 个百分点、波动大的组更宽，测试集 2500 张本身的标准误在 **0.2~0.6** 个百分点，所以除 **7.05** 的迁移优势外只能下「方向 + 量级」的结论；三是只做了一个数据集、没做交叉验证和 TTA；四是错误样本里有不少本身长得像另一类，纯视觉二分类有上限。
