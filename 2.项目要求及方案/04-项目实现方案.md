### 1.4 数据就绪检查脚本（可直接运行）

放到 `project/check_data.py` 即可，只依赖 `pathlib` + `Pillow`（`pip install pillow`），不依赖 torch：

```python
"""数据就绪自检：数量 / 类别 / 尺寸分布 / 损坏文件。
用法： python check_data.py "d:\DeepStudy\Project1\Cat_Dog_data"
"""
import sys
from pathlib import Path
from collections import Counter, defaultdict
from PIL import Image

EXPECT = {"train": {"cat": 11250, "dog": 11250},
          "test":  {"cat": 1250,  "dog": 1250}}
EXTS = {".jpg", ".jpeg", ".png", ".bmp", ".webp"}

def scan(root: Path):
    problems, stats = [], {}
    for split in ("train", "test"):
        for cls in ("cat", "dog"):
            d = root / split / cls
            if not d.is_dir():
                problems.append(f"[缺失目录] {d}")
                continue
            files = [p for p in d.iterdir() if p.suffix.lower() in EXTS]
            others = [p for p in d.iterdir() if p.is_file() and p.suffix.lower() not in EXTS]
            if others:
                problems.append(f"[非图片文件] {d} 下有 {len(others)} 个，例如 {others[0].name}")
            sizes, bad = [], []
            for p in files:
                try:
                    with Image.open(p) as im:
                        im.verify()                     # 快速校验文件完整性
                    with Image.open(p) as im:
                        sizes.append(im.size)           # (宽, 高)
                except Exception as e:
                    bad.append((p.name, str(e)))
            if bad:
                problems.append(f"[损坏/无法读取] {d} 有 {len(bad)} 张，例如 {bad[:3]}")
            expect = EXPECT[split][cls]
            if len(files) != expect:
                problems.append(f"[数量不符] {d}: 实际 {len(files)}，期望 {expect}")
            if sizes:
                ws = sorted(s[0] for s in sizes)
                hs = sorted(s[1] for s in sizes)
                med = lambda a: a[len(a) // 2]
                ratios = Counter(round(w / h, 2) for w, h in sizes)
                stats[f"{split}/{cls}"] = {
                    "count": len(files),
                    "w_min/med/max": (ws[0], med(ws), ws[-1]),
                    "h_min/med/max": (hs[0], med(hs), hs[-1]),
                    "aspect_top3": ratios.most_common(3),
                }
    return stats, problems

def main(root_str):
    root = Path(root_str)
    if not root.is_dir():
        print(f"根目录不存在：{root}"); return
    stats, problems = scan(root)
    print("=" * 68)
    for k, v in stats.items():
        print(f"{k:12s} 数量={v['count']:6d}  宽 min/中位/max={v['w_min/med/max']}  "
              f"高 min/中位/max={v['h_min/med/max']}")
        print(f"{'':12s} 长宽比 top3={v['aspect_top3']}")
    print("=" * 68)
    total = sum(v["count"] for v in stats.values())
    print(f"图片总数：{total}")
    n_train = sum(v["count"] for k, v in stats.items() if k.startswith("train"))
    n_test = sum(v["count"] for k, v in stats.items() if k.startswith("test"))
    print(f"训练:测试 = {n_train}:{n_test}（约 {n_train / max(n_test,1):.1f}:1）")
    if problems:
        print("\n发现问题：")
        for p in problems:
            print(" -", p)
    else:
        print("\n检查通过：目录结构、数量、文件完整性均正常。")
    print("\n注意：尺寸不统一是正常的，由 transforms.Resize + CenterCrop 统一到 224×224。")

if __name__ == "__main__":
    main(sys.argv[1] if len(sys.argv) > 1 else r"d:\DeepStudy\Project1\Cat_Dog_data")
```

**通过标准**（脚本输出应满足）：

- 四行统计分别为 11250 / 11250 / 1250 / 1250，总数 25000；
- 无 `[缺失目录]`、`[数量不符]`、`[损坏/无法读取]`；
- 宽、高的 min 明显小于 224（说明原图尺寸参差，必须 resize），长宽比 top3 不唯一（说明不能直接暴力 resize 到正方形，要 crop）。

> 若发现损坏图（Kaggle 原始包里偶有），处理策略：记入报告"数据清洗"小节，`ImageFolder` 默认遇到坏图会抛异常，可在自定义 Dataset 里包一层 `try/except` 跳过并计数——这本身就是"代码规范 10 分"和"结果分析"的加分素材。

## 2. 预处理与数据增强（对应"二"硬性要求 + 扣分项 −10）

### 2.1 具体 transforms 配置

```python
from torchvision import transforms

# ImageNet 统计量：与预训练权重对齐（迁移学习必须；自搭 CNN 用同一套也便于对比）
MEAN = [0.485, 0.456, 0.406]
STD  = [0.229, 0.224, 0.225]

train_tf = transforms.Compose([
    transforms.RandomResizedCrop(224, scale=(0.6, 1.0), ratio=(0.8, 1.25)),
    transforms.RandomHorizontalFlip(p=0.5),
    transforms.RandomRotation(degrees=12),
    transforms.ColorJitter(brightness=0.2, contrast=0.2, saturation=0.2, hue=0.02),
    transforms.ToTensor(),
    transforms.Normalize(MEAN, STD),
])

eval_tf = transforms.Compose([
    transforms.Resize(256),          # 短边缩到 256
    transforms.CenterCrop(224),      # 中心裁 224×224
    transforms.ToTensor(),
    transforms.Normalize(MEAN, STD),
])
```

参数逐项理由（也是答辩要说的话）：

| 变换 | 参数 | 为什么是這個值 |
|---|---|---|
| `RandomResizedCrop(224)` | `scale=(0.6,1.0)` | 原教程默认 `(0.08,1.0)` 太激进，会把猫裁成一只耳朵；0.6 起更温和，适合 2.2 万张的小数据集 |
| 同上 | `ratio=(0.8,1.25)` | 猫狗长宽比不会极端，限制范围避免过度形变 |
| `RandomHorizontalFlip` | `p=0.5` | 猫狗左右对称，零成本增强；**不能用垂直翻转**（狗倒过来不是自然样本） |
| `RandomRotation(12)` | 12° | 比教程的 30° 保守；超过 20° 常把目标转出画面、补黑边 |
| `ColorJitter` | 0.2/0.2/0.2/0.02 | 模拟不同光照与毛色；hue 很小，避免把橘猫染成绿猫 |
| `ToTensor` | — | HWC→CHW、0~255→0~1，必须 |
| `Normalize` | ImageNet 三均值/三标准差 | 迁移学习**必须**对齐预训练分布；自搭 CNN 用同一套，保证 E2 对比只有"模型"一个变量 |
| `Resize(256)+CenterCrop(224)` | — | 保长宽比、再裁中心，避免拉伸变形 |

### 2.2 为什么训练集与验证/测试集必须不同

1. **增强的本质是"制造随机扰动"**。它的收益只发生在**参数更新**时：让模型见过不同位置/尺度/光照下的同一只猫，从而学到不变性。
2. **评估要求可复现、可比较**。若测试时也随机裁剪，同一模型跑两次准确率能差 1~2 个点，你无法判断"改进"是真的还是噪声；答辩时也无法复现 PPT 上的数字。
3. **评估时用"确定性、居中、完整"的视图**，才对应真实部署场景（用户给一张完整照片，而不是随机裁掉 40% 的画面）。
4. **训练/测试的归一化必须完全一致**，这是唯一必须"相同"的部分；随机性部分必须"不同"。

→ 因此 `train_tf` 带 4 种随机变换，`eval_tf` 只有确定性的 Resize+Crop+ToTensor+Normalize，**验证集和测试集共用 `eval_tf`**。

这条直接对冲扣分项"未使用数据增强 −10 分"；同时 E1 实验（§5）用"关掉增强"的对照组，把"增强带来的提升"量化出来，正好落进评分项"对比数据增强策略对性能的影响"（选做加分）。

## 3. 自定义 CNN：结构表与设计理由

### 3.2 与评分要求的逐条核对

| 原文要求 | 本方案 | 状态 |
|---|---|---|
| ≥3 个卷积层 | 7 个 | 满足（2 倍余量） |
| ≥3 个池化层 | 4 个 | 满足 |
| ≥3 个全连接层 | 3 个（256→512→256→2） | 满足，**注意不是"2 个 FC + 1 个输出"以外的偷懒写法** |
| 批量归一化（选做加分） | Conv 后 BN2d ×7、FC 后 BN1d ×2 | 满足 |
| Dropout（抗过拟合） | 0.5 / 0.5 / 0.3 三处 | 满足 |
| 统一 224 输入 | 全流程 224 | 满足 |

### 3.3 几个关键取舍（答辩会被问）

1. **为什么用 4 次池化而不是 3 次**：224→112→56→28→14，最后 `14×14` 直接 GAP。若只池化 3 次，特征图 28×28，接 FC 时参数会翻 4 倍（`256*28*28*512 ≈ 1 亿`），在 2.2 万张图上必然过拟合。
2. **为什么用 GAP 而不是 `view + 大 FC`**：cifar10 那份 notebook 是 `64*4*4 → 500`（约 51 万参数）。本项目输入更大，若照搬会得到 `256*14*14 → 512 ≈ 2570 万` 参数，是本方案全部参数的 30 倍。GAP 把这部分压成 0，是"轻量化设计"（选做加分）的直接体现。**这个选择由 E7 做定量对照**（见 §5.4），不是只写在设计里。
3. **为什么每块放两个 3×3 conv**：VGG 的经验——两个 3×3 的感受野等于 5×5，但参数是 `2×9C²` 而非 `25C²`，且多一次 ReLU 带来更强非线性。
4. **BN 放 conv 之后、ReLU 之前**（`conv → bn → relu`）：这是主流顺序；若放 ReLU 之后，负值已被截断，BN 的均值校正作用会打折。
5. **学习率起点**：Adam `1e-3`（batch 32）。BN 网络对 lr 不敏感，但 `1e-2` 仍可能前期不稳定。
6. **正则组合**：BN + Dropout(0.5) + 数据增强 + 早停，四重防过拟合。若训练集准确率始终上不去（<85%），说明正则过强，先把 dropout2 降到 0.3。

## 4. 迁移学习：模型选择与两阶段微调

### 4.1 选型：ResNet18

| 候选 | 参数量 | 224 单张前向 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|---|
| **ResNet18** | 11.2M | 快 | 原文明确举例；残差结构易训；单卡/CPU 都能跑 | 精度略低于深层模型 | **主选** |
| VGG16 | 138M | 慢 3~5 倍 | 原文也举例；结构直观 | 全连接层巨大（1.2 亿参数）、显存占用高 | 备选（若老师要求） |
| ResNet50 | 25.6M | 中 | 精度更高 | 小数据集上收益有限，训练更久 | 不推荐（性价比低） |

**理由归纳**：① 评分标准原文点名 "如 VGG16、ResNet18"，选它零解释成本；② 11M 参数在 2.2 万张图上刚好，既不会欠拟合也不会因为太大而过拟合；③ 训练成本低，给 6 组对比实验留出时间预算（§7）；④ 残差连接让"解冻部分层微调"更稳（梯度不会在深层衰减）。

### 4.2 两阶段流程（对应"冻结部分层并微调分类头"；规避 −15 分）

```
阶段 A（只训分类头）
  backbone 全部 requires_grad=False
  新头: Dropout(0.3) → Linear(512, 2)
  optimizer 只接 head 参数，Adam lr=1e-3
  epochs=6，早停 patience=2（监控 val_loss）
        ↓
阶段 B（解冻最后 N 层微调）
  解冻 layer4（ResNet18 的最后一个 stage，含 2 个 BasicBlock）
  可训练参数 = layer4 + 新头
  分层学习率：backbone 1e-4，head 1e-4（或 head 保持 1e-3，二者都可，报告中说明）
  epochs=6，早停 patience=2
        ↓
  取 val_acc 最高的权重做最终测试
```

具体操作要点（第 3 轮实现时照此写）：

1. **冻结必须在换头之前**（Part 8 的坑：顺序反了会全体冻结、loss 不动且不报错）。自检：`sum(p.requires_grad for p in model.parameters())` 应等于"新头参数量"。
2. **`model.fc = nn.Sequential(nn.Dropout(0.3), nn.Linear(512, 2))`**。ResNet18 的 `fc.in_features=512`，不是 1024（DenseNet 才是 1024）。
3. **只把 head 参数交给阶段 A 的 optimizer**：`optim.Adam(model.fc.parameters(), lr=1e-3)`。
4. **阶段 B 重建 optimizer**：`optim.Adam([{'params': model.layer4.parameters(), 'lr': 1e-4}, {'params': model.fc.parameters(), 'lr': 1e-3}])`。绝不能复用阶段 A 的 optimizer——Adam 内部动量 state 里存着旧参数张量，复用会报设备/尺寸错误或静默失效。
5. **BN 的处理**：阶段 A 中 backbone 处于 `train()` 会让 BN 的 running stats 继续被小 batch 更新。两种做法都可，**推荐 A1**：
   - A1（推荐）：阶段 A 把 backbone 设为 `eval()`（BN 用 ImageNet 统计量、不更新），只让新头 `train()`。实现上是遍历 `model.modules()` 把 `BatchNorm2d` 设为 eval，训练循环末尾再统一 `model.train()` 前重置——稍繁琐但最稳。
   - A2（省事）：全程 `model.train()`，batch 32 的统计量也够稳，风险可控。
   - 报告里写清你选了哪种，以及为什么——这就是"能解释训练策略"的得分点。
6. **阶段 B 的 batch size**：若显存允许，提到 32~48；BN 在小 batch 下统计噪声大，容易把 pretrained 的统计量冲坏。
7. **必须给出两阶段对比数字**（阶段 A 结束 vs 阶段 B 结束的 val_acc / test_acc）。这既证明"确实微调了"（对冲 −15 分），又构成一组消融实验（E6）。

### 4.3 与"仅提交预训练模型且未微调 −15 分"的关系

该扣分项针对的是"直接 `pretrained=True` 然后 `predict`，完全不改分类头、不训练"。本方案做了三件明确的事：**换掉 1000 类分类头 → 只训新头 → 再解冻 layer4 微调**，并在报告中给出两阶段的 loss/acc 曲线。这三点齐备，就不存在被判"未微调"的空间。

## 5. 对比实验设计（对应"实验设计 25 分"，至少 3 组）

### 5.1 变量控制原则（先立规矩，否则实验无效）

- **同一份数据切分**：固定 `seed=42` 的 train/val 划分（train 20250 / val 2250，即 90/10），所有实验复用同一份索引，索引存成 `split_seed42.json`。
- **同一个测试集**：`Cat_Dog_data/test`（2500 张），只在最后评一次。
- **同一套评估代码**：同一个 `evaluate.py` 产出 acc / loss / 混淆矩阵，避免"评估方式不同"污染对比。
- **单一变量**：每组实验只改一个因素，其余全部固定（包括 epoch 数、batch size、优化器）。
- **每组的记录字段**：`实验编号 / 变量 / 训练时长 / best val_acc / test_acc / test_loss / 是否早停 / 曲线图路径 / 混淆矩阵路径`。
- **重复性**：关键结论（尤其 E2）建议跑 2~3 个 seed 取均值±标准差；时间不够则跑 1 个 seed 并在报告里说明局限。

### 5.2 实验总表

| **E6** | 是否解冻微调（阶段 A vs B） | 只训分类头（阶段 A 最佳权重） | 解冻 layer4 微调后（阶段 B 最佳权重） | 阶段 B 高 1~4 个点；若提升 <0.5 点，说明数据量不足以支撑更深微调，报告中如实分析 | 证明"确实做了微调"（对冲 −15）；兼作消融分析 |
| **E7** | 分类头聚合方式：GAP vs 展平+大 FC（轻量化主实验） | M-heavy：`Flatten(256*14*14) → Linear(50176,512)`，26.3M 参数 | M-gap：现有设计 `GAP → 512 → 256 → 2`，0.85M 参数 | 参数量/体积降约 31 倍；test_acc 持平或 GAP 高 0.5~1.5 点（heavy 版过拟合）；单 epoch 略快 | 选做"尝试轻量化设计"加分 + 实证 §3.3 的 GAP 选择 |
| **E8** | 通道宽度减半（轻量化第二档） | 宽度 32/64/128/256（§3 原版） | 宽度 16/32/64/128（约 0.28M 参数） | 参数降约 3 倍、单 epoch 快 25%~35%，test_acc 掉 1~2 点；用于画"参数量-准确率"权衡曲线 | 选做"轻量化"加分的第二档；兼作"结构设计合理性"分析 |

### 5.4 轻量化对比设计（E7 / E8，对应"尝试轻量化设计"加分项）

**为什么需要单独设计**：原文只写"尝试轻量化设计"，没给指标。如果只写一句"我用了 GAP 所以很轻"，评委会认为这是**设计选择**而不是**实验**。要拿加分，必须把"轻"量化成可比数字，并给出"轻了多少 / 精度掉了多少"的权衡。

#### E7（主实验，建议做）：分类头聚合方式 GAP vs 展平 + 大 FC

| | 对照组 M-heavy | 实验组 M-gap（§3 现有设计） |
|---|---|---|
| 卷积主干 | 完全相同（7 conv / 4 pool / BN） | 完全相同 |
| 分类头 | `Flatten(256*14*14=50176) → Linear(50176,512) → BN → ReLU → Dropout → Linear(512,2)` | `AdaptiveAvgPool2d(1) → Dropout → Linear(256,512) → …` |
| 参数量 | `50176*512+512 ≈ 25.69M` + 主干 0.585M ≈ **26.28M** | **0.85M** |
| fp32 权重体积 | 约 **100 MB** | 约 **3.3 MB** |
| 预期 test_acc | 92.0%±（过拟合，train-val gap 大） | 93.0%±（正则更充分） |
| 预期单 epoch | 23~25 s | 21~23 s |

**只改分类头、主干与所有超参完全不变**，否则无法归因。

#### E8（第二档，选做）：通道宽度减半

| | 对照组（§3 原版） | 实验组（half） |
|---|---|---|
| 各块通道 | 32 / 64 / 128 / 256 | 16 / 32 / 64 / 128 |
| 参数量 | 0.85M | 约 **0.28M** |
| 预期 test_acc | 93.0%± | 91.0%~92.0% |
| 预期单 epoch | 21~23 s | 14~16 s |

用途：和 E7 的两个点一起画"**参数量（横轴，对数）- 准确率（纵轴）**"散点图，说明"轻量化存在收益拐点"，而不是越轻越好。

#### 需要记录的轻量化指标（报告里放这张表）

| 指标 | 测量方法 | 单位 |
|---|---|---|
| 参数量 | `sum(p.numel() for p in model.parameters()) / 1e6` | M |
| 可训练参数量 | 同上，只统计 `p.requires_grad` | M |
| 权重体积 | `os.path.getsize('best.pt')/1024**2`（或 `params*4/1024**2` 估算 fp32） | MB |
| 单 epoch 训练时间 | 训练循环 wall-clock，注明是否含验证 | s |
| 单张推理时延 | batch=1，先 warmup 20 次，再测 100 次取均值；GPU 需 `torch.cuda.synchronize()` 前后夹 `time.perf_counter()` | ms/张 |
| 吞吐 | batch=32，`32 / 平均耗时` | img/s |
| FLOPs（可选） | PyTorch 2.x 内置 `torch.utils.flop_counter.FlopCounterMode` | GFLOPs |
| test_acc | 统一 `evaluate.py`，同一测试集 | % |

**公平性要求**（否则数据不可信）：同一台机器、同一 batch size、同一 AMP 开关、同一 `num_workers`；测时延时排除数据加载（只计 `model(x)`），且必须先 warmup；每个数字重复 3 次取中位数。

#### 报告里可直接用的结论话术

> GAP 版本把参数量从 26.3M 压到 0.85M（约 1/31）、权重体积从 100MB 压到 3.3MB，test_acc 不降反升 0.5~1.5 个点，说明原设计中的大 FC 层是纯粹的参数浪费；继续把通道减半（E8）可再降 3 倍参数，但准确率开始下降，因此 **GAP + 原宽度是性价比拐点**。

#### 一条边界（避免踩硬性要求）

**不要用"把输入从 224 降到 160/128"来做轻量化**——这违反原文"二、所有图像须统一尺寸（建议 224×224）"以及与预训练模型的对齐要求，属于"省错地方"。轻量化只能在**网络结构**上做文章（GAP、宽度、深度、分组卷积）。

## 6. 评估：四个产出分别怎么做

统一约定：`model.eval()` + `with torch.no_grad():`；先把整个测试集跑一遍，保存 `y_true / y_pred / y_prob`（numpy 数组）到 `outputs/runs/<实验编号>/preds.npz`，之后所有图表都从这份缓存生成，避免重复前向。

| 产出 | 库 | 关键函数 | 具体做法 | 对应评分 |
|---|---|---|---|---|
| **准确率** | `sklearn.metrics` | `accuracy_score(y_true, y_pred)`；二分类再算 `precision_score / recall_score / f1_score(average='binary')`、`roc_auc_score` | 测试集 2500 张一次性评估；报告里写"准确率 + 精确率 + 召回率 + F1 + AUC"五个数，比只报 acc 更专业 | 结果分析 20 分（≥80%，每 +2% 加 1 分，上限 95%） |
| **损失曲线** | `matplotlib.pyplot` | `plt.plot(epochs, train_loss, label='train')`、`plt.plot(epochs, val_loss)`；双轴或双子图再画 acc | 每个 epoch 记录 **样本平均** loss（`loss.item()*batch_size` 累加后除以样本数，别除以 batch 数）；`plt.savefig(..., dpi=150)` 存 PNG；训练时同步写 `history.csv` | 结果分析 + PPT 图表规范 |
| **混淆矩阵** | `sklearn.metrics` + `seaborn` 或纯 matplotlib | `confusion_matrix(y_true, y_pred, labels=[0,1])` → `sns.heatmap(cm, annot=True, fmt='d', cmap='Blues', xticklabels=['cat','dog'], yticklabels=['cat','dog'])` | 必须标清轴：x=预测、y=真值；再补充一行文字"cat→dog 误判 X 张，dog→cat 误判 Y 张"；可再加归一化版本（`normalize='true'`） | 结果分析明确要求"提供混淆矩阵" |
| **错误样本可视化** | `torch` + `matplotlib` | `torch.topk` / `argsort` 按"置信度"排序错误样本；`plt.subplots(3, 5)` + `ax.imshow` + `ax.set_title(f"P={pred} T={true} {conf:.2f}", color='red')` | 只挑 `y_pred != y_true` 的样本，按 `max(prob)` **从高到低**排——"高置信度错误"最有分析价值；每张图先做反标准化 `img*std+mean` 再 clip 到 [0,1]；分 3~5 类典型错误（如猫狗同色、遮挡、远景、多只动物）各举 1~2 例 | 结果分析明确要求"错误样本分析" |

补充两项（低成本高收益）：

- **训练/验证准确率双曲线**：与 loss 曲线同图或并排，直接支撑"过拟合/欠拟合"的判断（PPT 必放）。
- **`classification_report(y_true, y_pred, target_names=['cat','dog'])`**：一行拿到每类 precision/recall/F1，粘进报告即可。

### 7.4 跑得完的设计要点（也是省时间的工程手段）

1. **风险前置**：先跑 E6-A（3 分钟），确认能到 90%+，再展开其它实验。
2. **AMP 必开**：显存约降 30%、速度提升 30%~50%。
3. **早停**：patience=2，监控 `val_loss`；自搭 CNN 通常 18~22 epoch 就触发，省 1/3 时间。
4. **数据只解码一次**：22500 张 224×224 解码是大头。可选预处理成 256 短边的 `ImageFolder` 缓存（磁盘约 1~2GB），或直接把 `Resize(256)` 的结果缓存成 tensor 文件；不改也行，`num_workers=4` 基本能喂满。
5. **权重只存最优**：`if val_acc > best: torch.save(state_dict)`，避免每 epoch 写盘。
6. **实验可断点续跑**：每个 run 目录存 `config.yaml + history.csv + best.pt + last.pt`；崩了从 `last.pt` 续。
7. **OOM 兜底**：batch 32 → 16（同步把 lr 减半），或换 `ResNet18` 的 `weights=None` 分支排查是否预训练权重加载导致；224 输入在 8GB 上通常 3GB 以内，正常不会 OOM。
8. **没有 GPU 的兜底**：CPU 上 ResNet18 单 epoch 约 12~18 分钟，全套实验不可行。备选：① 用 Kaggle/Colab 免费 GPU（每周额度够跑完）；② 只跑必做三项 + 缩小到 10000 张子集（需在报告中说明并标注为"受限实验"）。
