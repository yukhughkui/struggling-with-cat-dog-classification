## 一、先建立直觉：这个项目在干什么

任务是二分类：给一张图，判断是猫还是狗。

数据在 `d:\DeepStudy\Project1\Cat_Dog_data`：

```
train/cat 11250 张 + train/dog 11250 张 = 22500 张（训练用）
test/cat  1250 张 + test/dog  1250 张 =  2500 张（最后才用）
```

训练时把 22500 张按 90:10 再切一刀：

- 20250 张做**训练集**：用来更新模型参数；
- 2250 张做**验证集**：每个 epoch 结束拿来看“学得怎么样”，用来选最优权重和早停；
- 2500 张测试集：全程不碰，最后每个 run 只评估一次，作为最终成绩。

> 为什么要有验证集？因为如果用测试集来挑模型，测试集就“泄题”了，成绩会虚高。验证集是“平时的模拟考”，测试集是“高考”。

项目最终做了 4 组对比实验（E1 增强、E2 自搭 vs 迁移、E6 冻结 vs 微调、E7 轻量化），每组 3 个随机种子，一共 15 个 run：

| 阶段 | run |
|---|---|
| 迁移学习 | `resnet_stageA_s42/43/44`、`resnet_stageB_s42/43/44`（6 个） |
| E1 自搭 CNN | `cnn_gap_aug_on_s42/43/44`、`cnn_gap_aug_off_s42/43/44`（6 个） |
| E7 自搭 CNN | `cnn_heavy_aug_on_s42/43/44`（3 个） |

最终主结果：ResNet18 阶段 B 测试准确率 **98.72% ± 0.18%**（3 个种子的均值 ± 标准差）。

## 二、名词小抄（第一次出现，用大白话说）

这些词后面每篇都会用到，先混个脸熟，不用背：

| 名词 | 一句话解释 |
|---|---|
| **张量（Tensor）** | 多维数组。一张彩色图是 `[3, 高, 宽]`，一批图是 `[B, 3, 高, 宽]`。 |
| **Dataset（数据集类）** | 一个“能按下标取样本”的列表：`ds[0]` 返回第 0 张图和它的标签。 |
| **DataLoader（数据搬运工）** | 把 Dataset 按 batch 打包、打乱、并行搬运给 GPU 的工具。 |
| **batch（批）** | 一次喂给 GPU 的一小批图，比如 32 张或 48 张。显存装不下全部 2 万张，所以分批喂。 |
| **epoch（轮）** | 把训练集完整看一遍叫 1 个 epoch。12 个 epoch 就是看 12 遍。 |
| **loss（损失）** | 一个数字，衡量“预测和答案差多远”。越小越好，但训练集 loss 太小可能是死记硬背。 |
| **optimizer（优化器）** | 根据 loss 自动调整模型参数的“调参器”，本项目用 Adam。 |
| **反向传播** | 从 loss 出发，倒着算每个参数“该往哪个方向调一点”，是 `loss.backward()` 干的事。 |
| **梯度清零** | 每批开始前把上一批留下的梯度擦掉，否则会累加。 |
| **冻结参数** | 把参数的 `requires_grad` 设成 False，反向传播时就不更新它。迁移学习第一阶段只训新分类头，靠的就是冻结。 |
| **迁移学习** | 借用在 ImageNet（1000 类）上已经学好的 ResNet18 特征，只改最后的分类头，再解冻一部分微调。 |
| **AMP（混合精度）** | 部分计算用 float16，速度快、省显存，用 `autocast + GradScaler` 实现。 |
| **早停（early stopping）** | 验证集连续几轮不再变好就提前结束，防止白跑和过拟合。 |
| **过拟合** | 训练集成绩很好、验证集不行，相当于把答案背下来了。数据增强和 Dropout 都是防它的。 |
| **混淆矩阵** | 一个 2×2 表格：行是真实类别，列是预测类别，一眼看出“猫被判成狗”有多少。 |
| **随机种子（seed）** | 控制随机数的起点。种子固定，数据打乱顺序、参数初始化就可复现。 |

## 三、一张图看懂：从 jpg 到准确率

```
磁盘 jpg
  Cat_Dog_data/train/{cat,dog}/*.jpg  (22500)
  Cat_Dog_data/test/{cat,dog}/*.jpg   (2500)
        │
        │ ① 只做一次：prepare_cache.py
        │    逐张解码 → 缩放到 256×256 → 存成 uint8 数组
        ▼
project/cache/train_256.npy  [22500,256,256,3]
project/cache/test_256.npy   [ 2500,256,256,3]
        │
        │ ② 每次取一个 batch：src/data.py
        │    CachedImageDataset.__getitem__ → [3,256,256] uint8
        │    DataLoader 拼成 [B,3,256,256] uint8
        ▼
训练循环（src/engine.py · train_one_epoch）
        │ ③ 搬到 GPU → 随机增强裁到 224 → /255 + 标准化
        ▼
模型前向（src/models.py · forward）
        │ ④ [B,3,224,224] → 卷积/池化 → [B,2] 两个类别的分数(logits)
        ▼
损失 + 反向传播（src/engine.py）
        │ ⑤ CrossEntropyLoss(logits, 标签) → loss.backward() → optimizer.step()
        ▼
每个 epoch 结束：验证集评估（engine.evaluate）
        │ ⑥ 得到 val_loss / val_acc → 存 best.pt，按 val_loss 判断要不要早停
        ▼
全部 epoch 结束：最终测试（src/runner.py · evaluate_on_test）
        │ ⑦ 载入 best.pt → 测试集 2500 张前向 → 准确率 + 预测结果
        ▼
出图（src/plots.py）→ test_cm.png / curves.png / test_errors.png
        │
        │ ⑧ 15 个 run 都完成后：summarize.py
        ▼
outputs/summary/experiment_summary.md + fig_E1/E2/E6/E7.png
```

## 四、两个嵌套循环到底在哪

这是读懂整个项目最关键的一点。其实是“三层”：

### 外层：15 个 run —— 在 `run_experiments.py` 的 `main()`

```python
for spec in specs:                      # 15 个配置，一个接一个跑
    if metrics_path.exists() and not args.force and not args.smoke:
        continue                        # 已经跑完的跳过（断点续跑）
    done.append(run_one(spec, ...))     # 真正跑一个 run
```

- `specs` 由 `build_specs(args)` 生成：6 个迁移 + 6 个 E1 + 3 个 E7 = 15。
- 每个 `spec` 只是一个字典，写着“这次用哪个模型、哪个种子、多少 epoch、要不要增强”。
- 每次循环调用 `runner.run_one(spec, ...)`，一个 run 从头训练到尾。
- 15 个 run 之间互不影响（除了阶段 B 要用阶段 A 的权重），所以可以一个个串行跑。

### 内层：一个 run 的 epoch —— 在 `src/engine.py` 的 `fit()`

```python
for epoch in range(1, epochs + 1):
    train_loss = train_one_epoch(...)   # 训练集过一遍
    val_loss, val_acc, ... = evaluate(...)  # 验证集过一遍
    ...                                 # 存最优、判断早停
```

- 这是“一个 run 内部”的循环，次数由 `spec["epochs"]` 决定（迁移 A 6 轮、B 8 轮、自搭 CNN 12 轮）。
- 每次循环结束会写一行 `history.csv`，记录这一轮的 loss 和准确率——`curves.png` 就是画它。
- 早停也在这里：如果验证 loss 连续 `patience` 轮不降，`break` 提前跳出。

### 最内层：一个 epoch 里的 batch —— 在 `train_one_epoch()` / `evaluate()`

```python
for images, targets in loader:          # 每次取 32 或 48 张
    ...
```

所以完整的三层是：

```
外层 15 个 run（run_experiments.py）
  └─ 中层 epoch 1..12（engine.py · fit）
       └─ 内层 batch 1..N（engine.py · train_one_epoch）
            每次 batch：前向 → loss → 反向 → 更新参数
```

记住这个结构，后面每篇文件都能对上号。

## 五、一个 run 的产物长什么样

每个 run 在 `outputs/results/<run_id>/` 下留这些文件：

| 文件 | 内容 |
|---|---|
| `config.json` | 这次跑的完整配置（模型、种子、epoch、batch、增强……） |
| `history.csv/json` | 每个 epoch 的 train_loss、val_loss、val_acc、耗时、学习率 |
| `best.pt` | 验证集上最好的权重 |
| `metrics.json` | 验证集最优准确率、参数量、训练时长、显存占用 |
| `model_structure.txt` | 模型结构打印（排查形状问题很有用） |
| `curves.png` | loss / val_acc 曲线 |
| `test_preds.npz` | 测试集真实标签、预测、概率 |
| `test_cm.png` | 测试集混淆矩阵 |
| `test_errors.png` | 置信度最高的 15 张错图 |
| `test_metrics.json` | 测试集准确率与 loss |

> 为什么“先存验证集最优，再单独评估测试集”？因为训练过程中只能看验证集；测试集只在最后跑一次前向，避免“边训边用测试集调参”。

## 六、建议的阅读顺序

1. **先看数据**（06）：知道一张图长什么样、一个 batch 长什么样。
2. **再看模型**（07）：知道输入输出形状怎么变。
3. **然后训练引擎**（08）：知道 loss 怎么算、参数怎么更新、早停怎么判断。
4. **再看 runner**（09）：知道上面三块怎么被串成一个 run。
5. **看 plots**（10）：知道成绩单怎么画出来。
6. **最后看三个入口脚本**（11–15）：知道 15 个 run 怎么被批量调度、怎么一键复现。
7. 辅助脚本 `check_data.py`、`prepare_cache.py` 可以最后看，它们不影响模型逻辑。

## 八、写在最后

这个项目的代码量不大（核心逻辑约 600 行），但它把“数据管道 → 模型 → 训练 → 评估 → 实验编排 → 汇总”整条链路都走了一遍。你不需要一次记住所有函数，只要记住三件事：

1. **数据永远以 `[B,3,256,256]` 的 uint8 张量流动**，在训练循环里才被裁到 224、标准化。
2. **一个 run = 一个 spec 字典 + `run_one()`**；15 个 run 就是外层一个 for 循环。
3. **训练循环三件套**：前向算 logits → CrossEntropyLoss → backward + optimizer.step。

接下来的每一篇，都会围绕这三件事展开。
