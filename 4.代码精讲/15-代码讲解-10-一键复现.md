# 代码讲解 10 · `一键复现.py`：不会命令行也能跑

> 位置：最外层的外层。它不是实验的一部分，而是“把四个脚本按顺序串起来”的自动化入口。
> 一句话职责：**双击或点 ▶，自动完成数据检查 → 缓存 → 15 个 run → 汇总，支持断点续跑。**

---

## 一、这个文件在链路中的位置

```
编辑器 ▶ / 双击
        │
        ▼
一键复现.py  ← 你在这一篇
    ├─ 选择装好 torch 的 Python
    ├─ 子进程调用 check_data.py       （第 1 步）
    ├─ 子进程调用 prepare_cache.py    （第 2 步，已有缓存则跳过）
    ├─ 子进程调用 run_experiments.py  （第 3–5 步：迁移 / E1 / E7）
    └─ 子进程调用 summarize.py        （第 6 步）
        │
        ▼
outputs/results/、outputs/summary/
```

它**不导入** `src` 里的任何模块，也不改变其他脚本的行为——只是替你在命令行里“敲”那几条命令。

---

## 二、常量与函数

| 名字 | 干什么 |
|---|---|
| `PROJECT_DIR` / `OUT_ROOT` / `DATA_ROOT` | 项目、输出、数据路径 |
| `SEEDS` / `TRANSFER_BATCH` / `CNN_BATCH` / `CNN_EPOCHS` | 与 README 一致的实验参数 |
| `TRANSFER_RUNS` / `E1_RUNS` / `E7_RUNS` | 每个阶段期望产出的 run_id |
| `StepError` | 自定义异常，用来统一提示“哪一步失败” |
| `_has_torch()` | 只检查 torch 包在不在，不真的 import |
| `pick_python()` | 挑一个能用的解释器 |
| `run_command()` | 跑子进程、实时转发输出、失败抛异常 |
| `_run_status()` / `incomplete_seeds()` / `need_retrain()` | 断点续跑判断 |
| `step_check_data()` / `step_prepare_cache()` / `step_group()` / `step_summarize()` | 六个步骤 |
| `main()` | 串起全流程、打印最终产物位置 |

## 三、逐段讲关键代码

### 3.1 参数：和 README 保持一致

```python
SEEDS = [42, 43, 44]
TRANSFER_BATCH = 32
CNN_BATCH = 48
CNN_EPOCHS = 12
HEAVY_EPOCHS = 12
```

- 这些就是 README 里“正式实验两条命令”的参数。**改这里等于改复现配置**。
- 为什么不从命令行读？因为目标用户不敲命令行。想改就改这几行。

```python
TRANSFER_RUNS = {s: [f"resnet_stageA_s{s}", f"resnet_stageB_s{s}"] for s in SEEDS}
```

- 用字典记下“每个种子应该产出哪些 run”。断点续跑就是拿它去比对磁盘。

### 3.2 `pick_python()`：双击时可能不是 torch_env

```python
candidates = [sys.executable, str(TORCH_ENV_PYTHON), shutil.which("python")]
for p in candidates:
    if p and Path(p).exists() and _has_torch(str(p)):
        return Path(p)
```

- 编辑器里点 ▶：`sys.executable` 就是你选的那个解释器，直接用。
- 双击：Windows 可能用系统默认 Python，里面没有 torch。于是退而求其次，试 README 里记录的 `torch_env` 路径，再试 PATH 里的 `python`。
- 都找不到就抛 `StepError`，并告诉你“去编辑器里选解释器”——这比抛一个 `ModuleNotFoundError: No module named 'torch'` 友好得多。

```python
code = "import importlib.util,sys;sys.exit(0 if importlib.util.find_spec('torch') else 1)"
```

- 用 `find_spec` 只查“包在不在”，**不 import torch**。因为本机 import torch 很慢（冷启动可能几分钟），检查解释器不该花这么久。

### 3.3 `run_command()`：跑子进程并实时显示

```python
env["PYTHONIOENCODING"] = "utf-8"
env["PYTHONUNBUFFERED"] = "1"
proc = subprocess.Popen([...], cwd=str(PROJECT_DIR),
                        stdout=subprocess.PIPE, stderr=subprocess.STDOUT,
                        text=True, encoding="utf-8", errors="replace", env=env)
for line in proc.stdout:
    print("  " + line, rstrip("\n"))
```

- 用 `subprocess.Popen` 而不是 `subprocess.run`：可以**一行一行实时转发**子进程输出，而不是等它跑完才一次性显示。训练一个多小时，实时进度很重要。
- `stderr=subprocess.STDOUT`：把报错也并进正常输出，不会漏。
- `PYTHONIOENCODING=utf-8` + `encoding="utf-8"`：子脚本打印中文，统一编码，避免 `UnicodeDecodeError`。
- `PYTHONUNBUFFERED=1`：子进程不攒缓冲，进度能立刻出现。
- `cwd=PROJECT_DIR`：保证子脚本里的相对路径（如 `cache/`）都对。

```python
if code != 0:
    raise StepError(f"步骤「{title}」失败（退出码 {code}），请把上面的报错信息发给我。")
```

- 任何一步返回非 0，就停下来，并且明确告诉你是哪一步。不会带着错误继续往下跑。

```python
except KeyboardInterrupt:
    proc.kill()
    proc.wait()
    raise
```

- 你按 Ctrl+C 时，先杀掉子进程再退出，避免留下一个还在训练的孤儿进程。

### 3.4 断点续跑：按 seed 判断

```python
def _run_status(run_id):
    d = RESULTS_DIR / run_id
    return (d / "metrics.json").exists(), (d / "test_metrics.json").exists()
```

- 一个 run“完整”= 训练完（有 `metrics.json`）且测试评估完（有 `test_metrics.json`）。

```python
def incomplete_seeds(group):
    seeds = []
    for seed, run_ids in group.items():
        if any(not all(_run_status(r)) for r in run_ids):
            seeds.append(seed)
    return seeds
```

- 只要某个种子的任何一个 run 不完整，这个种子就要处理；完整种子整体跳过。
- **为什么按 seed 而不是按 run**：`run_experiments.py` 的命令行只能按 seed 传（`--seeds 42`），不能只重跑某一个 run。按 seed 判断和它的接口对齐。

```python
def need_retrain(group, seeds):
    return any(not _run_status(r)[0] for s in seeds for r in group[s])
```

- 如果缺的是 `metrics.json` → 需要重训 → 命令加 `--force`（覆盖该 seed 的旧结果）。
- 如果只缺 `test_metrics.json` → 不用加 `--force`，`run_experiments.py` 会跳过训练、只补测试评估。这样不会因为“只差评估”而白训一遍。

**代价**：如果中断发生在某个种子的第 2 个 run（比如 stageB），续跑会把这个种子的 stageA 也重跑。这是“按 seed 续跑”的取舍；换成“按 run 续跑”需要改 `run_experiments.py` 的接口，超出这个文件的范围。

### 3.5 六个步骤

```python
step_check_data(python)
step_prepare_cache(python)
step_group(python, "[3/6] 迁移学习 …", TRANSFER_RUNS, [["transfer"], 32, [...]], ...)
step_group(python, "[4/6] 自搭 CNN · E1 …", E1_RUNS, [["e1"], 48, ["--epochs-cnn", "12"]], ...)
step_group(python, "[5/6] 自搭 CNN · E7 …", E7_RUNS, [["e7"], 48, ["--epochs-heavy", "12"]], ...)
step_summarize(python)
```

- **第 1 步**：先确认 `Cat_Dog_data` 存在，再跑 `check_data.py`，输出里必须有“检查通过”。没有就停——数据有问题，后面全是白跑。
- **第 2 步**：检查 `cache/train_256.npy` 和 `test_256.npy`，都在就打印大小并跳过；否则跑 `prepare_cache.py`（约 6 分钟）。
- **第 3–5 步**：`step_group()` 先判断哪些 seed 没跑完，再拼命令：

```python
cmd = [python, "run_experiments.py", "--only", *extra_args[0], "--seeds", *[...],
       "--batch-size", str(extra_args[1])] + extra_args[2]
if need_retrain(...):
    cmd.append("--force")
```

实际拼出来是：

```
python run_experiments.py --only transfer --seeds 42 43 44 --batch-size 32 --epochs-a 6 --epochs-b 8 --force
python run_experiments.py --only e1 --seeds 42 43 44 --batch-size 48 --epochs-cnn 12 --force
python run_experiments.py --only e7 --seeds 42 43 44 --batch-size 48 --epochs-heavy 12 --force
```

- **第 6 步**：`summarize.py` 很便宜，每次都跑，保证汇总表和图是最新的。

### 3.6 结尾：窗口别一闪而过

```python
def _pause_before_exit():
    try:
        if sys.stdin is not None and sys.stdin.isatty():
            input("\n按回车键关闭窗口...")
    except Exception:
        pass
```

- 双击运行时，脚本跑完控制台会立刻关闭，你来不及看结果。所以检测到“有交互终端”就等一次回车。
- 编辑器里点 ▶ 也能正常等待；如果环境没有 stdin，异常被吞掉，不影响退出。

## 四、如果你想改，改哪里

| 想做的事 | 改哪里 | 说明 |
|---|---|---|
| 只跑 2 个种子 | `SEEDS = [42, 43]` | 时间会缩短，但均值方差意义变弱 |
| 改 CNN 轮数 | `CNN_EPOCHS = 12` | 与报告对齐，别随便改成 20 |
| 改迁移 batch | `TRANSFER_BATCH = 32` | 显存不够就调小 |
| torch_env 换路径 | `TORCH_ENV_PYTHON` | 换电脑/换环境时必改 |
| 数据换位置 | `DATA_ROOT` | 同时要改 `run_experiments.py` 的 `DEFAULT_DATA` |
| 加一个新步骤 | `main()` 里加一行 `step_xxx(python)` | 新步骤内部用 `run_command()` |
| 每次都强制重跑 | 让 `incomplete_seeds` 永远返回全部种子 | 不推荐，1.7 小时起步 |
| 不要结尾暂停 | 删掉 `finally` 里的 `_pause_before_exit()` | 双击用户会看不到结果 |

## 五、新手易错点

1. **双击后报“找不到装好 PyTorch 的解释器”。**
   说明系统默认 Python 和 `torch_env` 都没有 torch，或 `torch_env` 路径变了。改 `TORCH_ENV_PYTHON`，或直接在编辑器里选解释器后点 ▶。

2. **同时开两个窗口一起跑。**
   两个进程会写同一批 `results/` 目录，互相覆盖权重和 json，结果不可信。一次只跑一个。

3. **以为“已完成的 run”会重新训练。**
   不会。脚本按 seed 检查 `metrics.json` 和 `test_metrics.json`，完整的直接跳过。想重跑某个种子，删掉 `outputs/results/*_s42/` 那些目录，或手动加 `--force` 跑原命令。

4. **中途关窗口，以为会接着跑。**
   关窗口会杀掉进程。已经写完的 run 会保留，重启脚本后从没完成的种子继续；当前正在跑的那个种子会从头再来。

5. **缓存存在但内容不完整。**
   一键脚本和 `prepare_cache.py` 都只检查 `.npy` 在不在。如果上次在写 labels 之前被杀掉，会出现“缓存已存在但训练报错”。处理办法：删掉 `project/cache/` 重新跑第 2 步。
