# 代码讲解 01 · `src/data.py`：数据从哪里来

> 位置：整条链路的**最上游**。所有模型看到的图，都从这个文件出去。
> 一句话职责：**把磁盘上的 jpg 变成 `[B,3,256,256]` 的 uint8 张量批次，并把训练集切成 90:10。**

---

## 一、这个文件在链路中的位置

```
check_data.py / prepare_cache.py（准备数据）
        │
        ▼
src/data.py  ← 你在这一篇
    make_loaders()
        ├─ CachedImageDataset / FolderImageDataset   （一张一张取图）
        ├─ split_indices()                           （90:10 切分）
        └─ DataLoader                                （打包成 batch）
        │
        ▼
src/engine.py（拿 batch 去做增强、训练）
```

它**不做**增强，也**不做**归一化。它只负责“把原图按统一尺寸搬出来”。
真正把图裁到 224、随机翻转、除以 255，是在 `engine.py` 的训练循环里做的（因为那些操作要放到 GPU 上）。

---

## 二、函数/类清单

| 名字 | 类型 | 干什么 |
|---|---|---|
| `MEAN` / `STD` | 常量 | ImageNet 的均值/标准差，标准化用 |
| `build_train_aug()` | 函数 | 造“训练用增强流水线”（在 GPU 上跑） |
| `build_eval_transform()` | 函数 | 造“验证/测试用流水线”（只中心裁剪） |
| `normalize_batch()` | 函数 | uint8 → float，除以 255 再标准化 |
| `CachedImageDataset` | 类 | 从 `.npy` 缓存里按下标取图（主路径） |
| `FolderImageDataset` | 类 | 直接从文件夹读 jpg（缓存不存在时的兜底） |
| `split_indices()` | 函数 | 打乱后切出训练/验证下标 |
| `make_loaders()` | 函数 | 组装三个 DataLoader，返回给 runner |
| `dump_split()` | 函数 | 把切分信息写 json（预留的审计工具，当前主流程没调用） |

## 三、逐段讲关键代码

### 3.1 两个常量：MEAN / STD

```python
MEAN = (0.485, 0.456, 0.406)
STD  = (0.229, 0.224, 0.225)
```

这是 ImageNet 数据集统计出来的三个通道平均值和标准差。

- **为什么要用它们**：ResNet18 的预训练权重是在“减过这组均值、除过这组标准差”的图上学的。你不按同样方式处理，输入分布对不上，预训练特征就不好用。
- **为什么自搭 CNN 也用同一套**：为了让 E2（自搭 vs 迁移）只差“模型”这一个变量。如果自搭 CNN 用别的标准化方式，比输了就说不清是模型差还是预处理差。
- **删了会怎样**：数值范围变成 0~255（或 0~1 但不居中），梯度会非常大，训练容易发散或极慢。

### 3.2 训练增强：`build_train_aug()`

```python
v2.RandomResizedCrop(size, scale=(0.6, 1.0), ratio=(0.8, 1.25), antialias=True)
v2.RandomHorizontalFlip(p=0.5)
v2.RandomRotation(degrees=12)
v2.ColorJitter(brightness=0.2, contrast=0.2, saturation=0.2, hue=0.02)
```

逐个说：

- **RandomResizedCrop(224)**：随机取原图 60%~100% 面积的一块（长宽比在 0.8~1.25 之间），再缩放到 224×224。等价于“随机放大、随机挪位置”，强迫模型别只认某个固定角落。
  - `scale=(0.6,1.0)`：至少保留 60% 画面，避免裁得太狠把猫裁没了。
  - `ratio`：允许轻微变形，但不能把猫拉成长条。
  - `antialias=True`：缩放时抗锯齿，图更干净。
- **RandomHorizontalFlip(0.5)**：一半概率左右翻转。猫翻过来还是猫，这是最便宜有效的一种增强。
- **RandomRotation(12)**：随机转 ±12°。手机拍的照片常常是歪的。
- **ColorJitter(0.2,0.2,0.2,0.02)**：亮度、对比度、饱和度、色调各自小幅随机变化，模拟不同光线。

对照组（`augment=False`）只做：

```python
v2.Compose([v2.CenterCrop(size)])
```

即从 256×256 缓存的正中间裁 224×224，**没有任何随机性**。E1 实验就是拿这一组和上面那组比。

> 注意：这些操作写的是 `v2`（torchvision 新版接口），可以直接吃 GPU 上的 uint8 张量。老接口 `torchvision.transforms` 只能处理 PIL 图、在 CPU 上跑，会很慢。

**删掉某一行会怎样**：
- 删 `RandomRotation`：模型对歪图更敏感，但训练更快；
- 删 `ColorJitter`：不同光照下的泛化会差一些；
- 全删（连 CenterCrop 都删）：输入变 256×256，后面模型的 14×14 展平尺寸就对不上，`Linear` 会报形状错误。

### 3.3 验证/测试流水线：`build_eval_transform()`

```python
return v2.Compose([v2.CenterCrop(size)])
```

验证和测试**绝对不能有随机性**。同一张图每次评估必须得到同样的结果，否则你没法判断“这轮到底变好了没有”。

> 常见误区：训练用随机裁剪、测试也随机裁剪，然后发现两次评估准确率差 1%，以为是模型不稳定，其实是评估方式不稳定。

### 3.4 标准化：`normalize_batch()`

```python
x = x_uint8.float().div_(255.0)
mean = torch.tensor(MEAN, device=x.device, dtype=x.dtype).view(1, 3, 1, 1)
std  = torch.tensor(STD,  device=x.device, dtype=x.dtype).view(1, 3, 1, 1)
return (x - mean) / std
```

- `x_uint8` 形状 `[B,3,224,224]`，值 0~255 的整数。
- `.float().div_(255.0)`：变成 0~1 的浮点数。**不除 255 会怎样**：数值大 255 倍，梯度爆炸，loss 变成 nan。
- `.view(1,3,1,1)`：把长度为 3 的均值向量变成“1×3×1×1”，这样能和 `[B,3,H,W]` 自动广播——每张图的每个通道减自己的均值。**不 view 会怎样**：形状对不上，直接报错。
- 这里是“先减均值再除标准差”，标准做法。

### 3.5 主路径：`CachedImageDataset`

```python
self.arr = np.load(arr_path, mmap_mode="r")
...
arr = np.array(self.arr[i])
img = torch.from_numpy(arr).permute(2, 0, 1).contiguous()
return img, int(self.labels[i])
```

- `mmap_mode="r"`：**不把 4.4GB 的训练集全读进内存**，而是用到哪张映射哪张。删掉 mmap，22500×256×256×3 字节约 4.4GB，16GB 内存的机器会很紧张。
- `np.array(self.arr[i])`：复制一份。**为什么复制**：memmap 是只读的，PyTorch 对只读 numpy 数组会警告“写入行为未定义”。删掉复制，会刷一屏 UserWarning。
- `permute(2,0,1)`：numpy 是 `[高,宽,通道]`（HWC），PyTorch 要 `[通道,高,宽]`（CHW）。**不 permute**：模型会把“宽”当通道，直接形状错误。
- `.contiguous()`：permute 之后内存不连续，转成连续内存，后面算子更快、也不会出怪问题。
- 返回的图是 **uint8**，不是 float——这是有意的，增强在 GPU 上做，uint8 传输更省带宽。

`__len__` 返回标签数量，DataLoader 靠它知道一共有多少样本。

### 3.6 兜底：`FolderImageDataset`

结构和 `CachedImageDataset` 一样，只是 `__getitem__` 里现场 `Image.open` + 缩放 + 中心裁剪到 256×256。

- 什么时候用：缓存还没生成时（`make_loaders` 里检测不到 `.npy` 就走这里）。
- **删了会怎样**：没缓存时直接报错，没法训练。但只要有缓存，这条路径永远不会执行。
- 它比缓存慢很多：每个 epoch 都要重新解码 2 万张 jpg。

### 3.7 切分：`split_indices()`

```python
idx = np.random.RandomState(seed).permutation(n)
n_val = int(round(n * valid_size))
return idx[n_val:], idx[:n_val]
```

这是整个文件里最容易写错的地方。

- 先用固定种子把 22500 个下标**整体打乱**，再切前 2250 个做验证。
- **为什么必须先打乱**：缓存的顺序是“按类别目录字母序 + 文件名排序”，前 11250 个全是猫。如果直接 `idx[:2250]`，验证集会**全是猫**，准确率就变成毫无意义的 50%。
- `seed` 固定为 42（`split_seed`），所以每次划分完全一样——这是实验公平性的基础：15 个 run 必须用同一套训练/验证划分。
- **删掉 permutation**：验证集类别单一，val_acc 永远 0.5 左右，你会怀疑模型坏了。

### 3.8 总装：`make_loaders()`

```python
train_ds = CachedImageDataset(train_arr, cache / "train_labels.npy")
val_ds   = CachedImageDataset(train_arr, cache / "train_labels.npy")
test_ds  = CachedImageDataset(test_arr,  cache / "test_labels.npy")
...
train_idx, val_idx = split_indices(len(train_ds), valid_size, seed)
train_set = Subset(train_ds, train_idx.tolist())
val_set   = Subset(val_ds,   val_idx.tolist())
```

- 训练集和验证集**共用同一个缓存数组**，只是用 `Subset` 挂上不同的下标。这样不会多占一倍内存。
- `Subset` 是 PyTorch 自带的小工具：“我只要原数据集里的这些下标”。
- 测试集是独立的 2500 张。

```python
train_loader = DataLoader(train_set, batch_size=batch_size, shuffle=True, ...)
val_loader   = DataLoader(val_set,   batch_size=batch_size, shuffle=False, ...)
test_loader  = DataLoader(test_ds,   batch_size=batch_size, shuffle=False, ...)
```

- **只有训练集 `shuffle=True`**：每个 epoch 打乱顺序，防止模型记住“第几个样本是什么”。验证/测试不需要打乱。
- 每个 batch 出来是：
  - `images`：`[B, 3, 256, 256]`，`torch.uint8`
  - `labels`：`[B]`，`torch.int64`，0=cat，1=dog
- `pin_memory=True`：把数据放在“锁页内存”，GPU 读取更快。
- `num_workers=0`：**本机是 Windows，DataLoader 每开一个子进程都要重新 `import torch`（实测冷启动约 247 秒）**，所以干脆不用多进程，靠预解码缓存 + GPU 增强来提速。你在别的机器上可以把 `num_workers` 调到 4~8。
- `persistent_workers=num_workers > 0`：只有多进程时才需要“保持 worker 存活”；0 的时候必须为 False。

### 3.9 预留工具：`dump_split()`

把“用了哪个种子、切了多少张、前 20 个下标是什么”写进 json。当前主流程没有调用它，属于可选的审计工具。你想在报告里证明“划分可复现”，可以手动调一次。

## 四、如果你想改，改哪里

| 想做的事 | 改哪里 | 怎么改 |
|---|---|---|
| 改输入分辨率（比如 128） | `build_train_aug(size=...)`、`build_eval_transform(size=...)` 的调用处（目前在 `runner.py` 里写死 224），**同时**改 `models.py` 里 `c4*14*14` 这个写死的展平尺寸 | 改小分辨率能显著提速，但准确率会掉 |
| 加一种增强（比如随机灰度） | `build_train_aug()` 里的 `Compose([...])` | 加一行 `v2.RandomGrayscale(p=0.1)` |
| 调增强强度 | `build_train_aug()` 里的参数 | 例如 `RandomRotation(degrees=20)`、`scale=(0.4,1.0)` |
| 改验证集比例 | `run_experiments.py` 里 `base = dict(valid_size=0.1, ...)` | 改成 0.15 就是 85:15 |
| 改切分种子 | `run_experiments.py` 的 `split_seed=42` | 一般不要改，否则和已有结果不可比 |
| 换数据目录 | `run_experiments.py --data-root` 或 `make_loaders(data_root=...)` | 目录必须是 `train/cat`、`train/dog`、`test/cat`、`test/dog` |
| 改 batch 大小 | 命令行 `--batch-size`（`run_experiments.py`） | 显存不够就调小 |
| 用多进程加速 | `run_experiments.py --num-workers 4` | 只在 Linux 或 torch 已缓存启动时值得开 |
| 换标准化参数 | `MEAN` / `STD` | 除非换预训练模型，一般别动 |

## 五、新手易错点

1. **以为 dataset 里已经做了 resize 和增强。**
   实际上 `CachedImageDataset` 只返回 256×256 的原始 uint8 图；裁剪到 224、翻转、标准化，全在 `engine.py` 的训练循环里。改增强要去 `build_train_aug()`，不是改 Dataset。

2. **先切分再打乱。**
   `split_indices` 必须“先 permutation 再切”。如果你自己写代码时写成 `idx[:n_val]` 直接切，验证集会全是猫（因为缓存按类别排序），准确率永远 50%。

3. **训练集 shuffle、验证集也 shuffle，或者反了。**
   只有训练集要 `shuffle=True`。验证/测试打乱不会改变准确率，但会让“错误样本图”的展示顺序每次不同，排查问题时很烦。

4. **在 Windows 上随手开 `num_workers=8`。**
   会看到 GPU 利用率 0%、风扇不转、几分钟没输出——每个子进程都在重新 import torch。本项目的默认 0 是有原因的。

5. **改了缓存尺寸却没改模型。**
   缓存是 256，模型里 `c4*14*14` 是按 224 输入、4 次池化算出来的。如果你把输入改成 192，池化后是 12×12，展平尺寸就错了，`Linear` 会报 `mat1 and mat2 shapes cannot be multiplied`。
